## 0. 为什么是 MST + 基准监测（而不是 CAT）

| 方案 | 优点 | 成本/风险 | 我们的结论 |
|---|---|---|---|
| IRT-CAT（逐题自适应，DET 路线） | 精度最高、题量最省 | 每题需参数校准（经验值 200–400 人/题）；题库与曝光控制复杂；低龄场景频繁换题易焦虑 | **中期不做** |
| **MST（多阶段自适应，TOEFL iBT 2026 路线）** | 精度接近 CAT（约 90–95%）；**按模块施测**、可解释、题目曝光可控、等值容易做 | 需要 3 级难度模块 × 多阶段题库 | **采用** |
| 线性固定卷（IELTS/剑桥路线） | 最易解释、等值成熟 | 无法解决"低龄与高龄同卷"，题量固定 | 作为基准测（短表）采用 |
| **基准 + 进度监测（WIDA/MAP/DIBELS 路线）** | 能画成长曲线；家长看得懂"进步了多少"；适合 4–6 周复测 | 需要平行卷 + 纵向量表 | **采用** |

一句话：**入学分档用 MST（一次、要准）；日常用基准短测 + 进度监测（高频、要能看趋势）。**

## 1. MST 结构（每个学生一次施测 = 49 题）

| 阶段 | 模块 | 题量 | 作用 |
|---|---|---|---|
| 0 | **Router 混合卷** | 12（基础/达标/挑战各 4） | 估计初始能力 θ₀，决定第一段难度 |
| 1 | **Stage 1 模块**（低/中/高三档之一） | 14 | 修正 θ；决定第二段难度 |
| 2 | **Stage 2 模块**（低/中/高三档之一） | 14 | 收敛 θ；提高分档精度 |
| 3 | **Performance 固定块**（口语 4 + 写作 4 + 锚题 1） | 9 | 产出型技能不做自适应，保证可比 |

**路由规则**（θ 为 1PL 能力估计，单位 logit）：

| θ 区间 | 判为 | Stage1 模块 | Stage2（据 θ₁ 再选，允许上下移动） |
|---|---|---|---|
| θ < −1.0 | 低 | 低档（基础为主） | 低 / 中（θ₁ ≥ −0.5 则升中） |
| −1.0 ≤ θ < 1.0 | 中 | 中档（达标为主） | 低 / 中 / 高（±0.5 步长） |
| θ ≥ 1.0 | 高 | 高档（挑战为主） | 中 / 高（θ₁ < 0.5 则降中） |

**关键纪律**：Stage 模块**学生之间必须不同**（同模块不同题序），且**同一次施测内不得重复用题**；Route/Stage 的题目按"离目标难度最近"贪心选取（题库扩容后改为固定模块）。

### 1.1 θ 估计（当前可实现版）
- 模型：1PL/Rasch，题目难度 b 用 tier 映射：tier1 = −1.0、tier2 = 0、tier3 = +1.0（题库校准后换成真实 b 参数）。
- 估计：θ 网格（−3…+3，步长 0.1）取似然最大；样本 ≥12 题后开始输出。
- 输出：`θ` → 量尺分 `0–100`（`100×(θ+3)/6`，截断）→ CEFR 档（A1 θ<−1；A2 −1~0；B1 0~1；B2 >1）。
- 置信区间：SE = 1/√信息量，报告给 `±1.96×SE`（v1 用近似值，v2 校准后替换）。

## 2. 题库需求（诚实账）

一次施测 49 题，但 MST 要求**每个阶段每档都有独立模块**：

| 资产 | 每个等级（A1/A2/B1/B2 各一份） | 4 档合计 |
|---|---|---|
| Router 混合卷 | 12 | 48 |
| Stage1 低/中/高模块 | 3×14 = 42 | 168 |
| Stage2 低/中/高模块 | 3×14 = 42 | 168 |
| Performance 固定块 | 9 | 36 |
| **合计** | **105** | **420** |

当前题库 49/档（196 题）→ **需扩到 105/档（420 题）**，即再补 224 题。
- 扩容优先级：Stage 模块（低/高档最缺）→ 平行基准卷 → 锚题。
- 每档模块按技能配比：词汇/语法 40%、听力 25%、阅读 25%、口语/写作 10%。

### 2.1 校准计划
1. **试点**（题库 105/档后）：≥60 名学生全路径作答，估计每题 b 与区分度。
2. **参数稳定**：单题有效样本 ≥200（低龄可放宽到 ≥120），每轮迭代重估。
3. **等值**：Router 内嵌 6 道锚题（跨年度固定），用锚题做年度等值。
4. **验收指标**：分档重测一致率 ≥80%；θ 与人工评分相关 ≥0.80（口语单列）；模块间难度顺序符合设计（低<中<高）。

## 3. 基准 + 进度监测（高频层）

| 项 | 设计 |
|---|---|
| 基准短测 | **24 题**（4 档 × 3 难度 × 2 题），约 12 分钟；每次从平行卷池按周轮换 |
| 平行卷 | 需 ≥3 套（3×24=72 题/档，含锚题保证可比）；当前 P0 用单一 24 题锚卷 |
| 量尺 | 与 MST 同一 θ→0–100 量表（同一套锚题等值）；**量尺分只内部用** |
| 家长可见 | **只给档位 + 档位区间 + 趋势**（量尺分、θ、SE 均不对外） |
| 复测节奏 | **每 4 周一次**（2026-11-10 决策）；首页显示上次时间与下次到期日 |
| 输出 | 档位（含区间，如 A2–B1）+ 成长曲线（最近 8 次，纵轴为档位 A1→B2）+ 变化判定 |
| 预警 | 档位变化且超过测量误差才说"升/降档"；否则一律"基本持平" |

**为什么基准测是 24 题而不是 12 题**：12 题时 θ 的 SE≈0.8–1.5，换算到量尺约 ±20–37 分，档位判定太不可靠。24 题把误差压到可接受范围，同时仍在 12 分钟内——这是"4 周一次"节奏能坚持的上限。

**"进步"的判定必须带误差带**：只有档位变化超过测量误差（约 ±5 分量尺分对应）时才对外说"升档/降档"，否则只说"基本持平"。这是 WIDA 置信带 / IELTS SEM 的做法，也是对家长负责的做法。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 题库不足导致模块复用（同题出现在不同学生不同阶段） | P0 用贪心选题并记录复用；P1 扩容后禁止跨模块复用 |
| tier 当 b 参数不准（过度简化） | P2 校准；报告注明"未校准前只作分档参考" |
| 低龄焦虑（频繁换难度） | 模块级切换而非逐题切换；UI 不显示难度变化 |
| 家长误读成长曲线 | 曲线必须带误差带；变化未超误差时不标"进步" |
| 基准卷泄题 | 平行卷轮换 + 锚题 + 学校侧随机化 |

### 7.1 Azure PA 接入说明
- 环境变量：`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`（可选 `AZURE_PA_LOCALE`，默认 en-US）。
- 前端：`MediaRecorder` 录音 → `AudioContext` 解码 → 重采样 16k → PCM16 WAV → base64 → `POST /api/pronunciation`。
- 请求参数：`GradingSystem=HundredMark`、`Granularity=Phoneme`、`Dimension=Comprehensive`、`EnableProsodyAssessment=true`、`EnableMiscue=true`。
- 返回字段：准确度 / 流利度 / 完整度 / 发音总分 / 韵律 + 逐词错误类型。
- 口径：发音分**只用于内部与老师反馈**，不进入家长版报告；未配置时明确显示"暂不可用"。

### 7.2 下一步（P1/P2）
1. 题库扩到 105/档、模块固定化、3 套平行基准卷 + 锚题等值。
2. 60 人试点校准 `b` 参数；重算切点与 SE；重测一致率 ≥80%。
3. 发音分接入报告内部区，并与人工评分做一致性验证（目标 ≥0.80）。
